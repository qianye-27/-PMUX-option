## 等价性验证说明（eqy）

### 1. 官方口径
9月24-28日答疑·赛题二第54问第3点：eqy 验证的是 **abc 之后的 `$lut` 网表**——因为完全映射成 cycloneiv 单元
（`cycloneiv_lcell_comb`/`dffeas` 等）以后，eqy 认不出这些单元的功能。
所以我们用优化版 yosys 综合到 `begin:map_cells`（abc 之后、单元映射之前），
`write_rtlil -selected` 只导出顶层，得到只含 `$lut` + `dffeas` 的门级网表。

### 2. 两侧怎么准备
- **gold**：`read_verilog case.v; prep -top <top>`，再做 `memory -nomap; memory_map; opt -fast`
  （否则 test4 的 case 表会以 `$mem_v2` 形式存在，与 gate 形态不一致，eqy 无法配对）。
- **gate**：`read_rtlil gate_<top>.il`，然后 `techmap -autoproc -map dffeas_sim.v`
  把 `dffeas` 还原成通用触发器。`dffeas_sim.v` 是专门写的最小行为模型
  （异步低电平清零 + 时钟使能 + 按 `power_up` 置初值）；用官方 `cells_sim.v` 的模型会推出 latch，
  SAT 解不出来。

### 3. test3 为什么会报 "Failed to prove"
eqy 默认按**输出**把设计切成若干分区，每个分区单独证明。
test3 是「移位寄存器 + 组合逻辑」的混合结构，它的正确性依赖一个**跨触发器的不变式**；
分区把这条边切断后，`sr`、`rw` 两个分区在各自的抽象里都不成立，于是推不出来。
**这是分区抽象的固有局限，与是否做优化无关**——同一赛题的其他参赛队也报告了完全相同的情况
（答疑 B53 问题 5），原版基线同样过不了。

### 4. 我们怎么处理（依据哪条答疑）
答疑 **9月24-28日答疑·赛题二EQY第5问** 原文：「**切换设计模式验证是允许的，算作通过**」。
因此 `run_eqy.ps1` 的策略是：

1. 先跑 eqy 分区模式（默认方式）；
2. 若 eqy 返回失败，**自动改用整设计 miter + SAT 时间归纳**再证一次：
   `miter -equiv gold gate miter` → `sat -verify -prove-asserts -tempinduct`；
3. 两种方式都失败，才打印 `FAIL`。

对 test3，miter 日志里能看到：
`Base case for induction length 1 proven` 与 `Induction step proven: SUCCESS!`，
比较的是 `gate_sr_out` / `gold_sr_out`、`gate_gpioout` / `gold_gpioout` 等输出，属于整设计等价。
所以脚本输出：

```
PASS  test3   (eqy partition inconclusive; whole-design miter proved equivalence)
note: 1 case(s) were proven with the whole-design miter because eqy partitioning cut a cross-flip-flop invariant.
      Switching verification mode is explicitly allowed (answer 9月24-28日答疑·赛题二EQY第5问); details in results_<case>_miter.log.
eqy result: PASS 9 / FAIL 0
```

### 5. 证据文件在哪
`verify/eqy/results/`
- `test1.log` … `pmux_case05_nested.log`：各用例的 eqy 原始输出（8 个分区模式 PASS）；
- `test3.log`：test3 的分区模式原始日志（**保留它以证明"分区不收敛"这个事实**，其中两行
  `Failed to prove ... sr/rw` 不是功能不等价）；
- `test3_miter.log`：test3 的整设计 miter 证明日志（base case + induction step 均成功）；
- `SUMMARY.txt`：一页式汇总，开头即 `TOTAL: 9 / 9 PASS`，并解释 test3 的判定依据。

### 6. 复现命令
```bat
cd <包根>\verify\eqy
run_eqy.bat -Cases ..\..\case          :: 完整包含 case/；官方包用 -Cases <9 个用例所在目录>
```
`run_eqy.bat` 会自动查找 OSS CAD Suite（`C:\oss-cad-suite`、`C:\tools\oss-cad-suite`、
`<包>\..\tools\oss-cad-suite` 等，最多向上找 6 层），找到后 `call environment.bat`，
再调用 `run_eqy.ps1`。找不到时会在 PowerShell 里提示用 `$env:OSS_CAD = "<路径>"` 指定
（注意 PowerShell 里 `set` 只建变量，不是环境变量）。

HOW test3 IS JUDGED
-------------------
`run_eqy.ps1` runs eqy in partition mode first (results/test3.log). For test3 the
partitions "sr" and "rw" cannot be proven in isolation, because partitioning cuts a
cross-flip-flop invariant that only holds for the whole design -- this is a property of
the partition abstraction, not an inequivalence, and it happens for the unmodified
baseline as well.

The script therefore re-checks that case with a whole-design miter + SAT temporal
induction (results/test3_miter.log), which reports
  "Base case for induction length 1 proven"  and
  "Induction step proven: SUCCESS!"
on a miter comparing gold/gate outputs (sr_out, gpioout).

Switching verification mode is explicitly allowed by the organisers
(answer 9月24-28日答疑·赛题二EQY第5问: "switching design mode for verification is allowed and counts as passed"),
so the case is reported as PASS. A case is reported as FAIL only if both methods fail.

The raw partition log is kept as evidence; do not read its two "Failed to prove" lines
as a functional mismatch.
